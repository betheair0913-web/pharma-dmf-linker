# 원료의약품등록 모니터링 시스템 (Pharma-DMF Linker)

식약처 공공데이터 Open API로 **원료의약품 등록(DMF)** 정보와 **완제의약품 허가** 정보를
수집해, 정규화된 성분 키로 교차 결합(N:M)하고 월별 변경 이력을 추적하는 Streamlit 웹 앱입니다.

대상 사용자: 제약·바이오 구매기획, SCM, 대외협력, RA(규제과학).

---

## 1. 빠른 시작

```bash
pip install -r requirements.txt
streamlit run app.py
```

Windows에서는 **`run.bat` 을 더블클릭**하면 서버가 뜨고 12초 뒤 브라우저가 자동으로 열립니다
(`http://localhost:8501`). 종료는 그 창에서 `Ctrl + C`.

> **`.streamlit/config.toml` 의 `server.headless = true` 를 끄지 마세요.**
> `false` 이면 Streamlit 이 최초 실행 시 콘솔에서 이메일 주소 입력을 기다리며 멈춰,
> 배치 파일로 실행할 때 서버가 뜨지 않은 것처럼 보입니다. 브라우저는 `run.bat` 이 직접 엽니다.
>
> 배치 파일(`run.bat`, `_open_browser.bat`)은 **ASCII + CRLF** 로 유지해야 합니다.
> UTF-8 한글 주석이나 LF 줄바꿈이 섞이면 cmd.exe 가 잘못 해석합니다.

브라우저가 열리면 **⚙️ 데이터 동기화** 페이지에서

1. 공공데이터포털 인증키를 입력하고 **저장** → **연결 테스트**
2. **🚀 전체 수집(Full Sync)** 실행 (약 4분, 약 800MB 전송)

수집이 끝나면 상세 조회·종합 현황·변경 이력 페이지를 쓸 수 있습니다.

인증키는 `.env` 로도 넣을 수 있습니다.

```
DATA_GO_KR_SERVICE_KEY=발급받은_인증키
```

Encoding 키(`%2B`, `%3D` 포함)와 Decoding 키 **어느 쪽이든** 동작합니다.
앱이 내부적으로 한 번 디코딩한 뒤 다시 인코딩하기 때문입니다.

## 2. 연동 API

| 구분 | 서비스 | 오퍼레이션 | 총 건수 |
|---|---|---|---|
| 원료의약품 등록(DMF) | `MdcDmfInfoService01` | `getMdcDmfList01` | 약 9,100 |
| 의약품 제품 허가정보 | `DrugPrdtPrmsnInfoService07` | `getDrugPrdtPrmsnDtlInq06` | 약 43,000 |

두 API 모두 페이지당 최대 **500건**까지 응답합니다(1000은 실패).
수집은 1페이지로 `totalCount`를 확인한 뒤 나머지를 세마포어(기본 동시 6)로 병렬 호출하며,
429/5xx/타임아웃은 지수 백오프로 최대 4회 재시도합니다.

### API 스펙상의 제약과 대응

| 제약 | 대응 |
|---|---|
| DMF에 **영문 성분명이 없음** | 완제 API의 단일제(주성분 1개)에서 `정규화 키 → 영문명` 쌍을 만들어 역매핑. 약 90%의 DMF에 영문명이 채워집니다. |
| DMF에 **등록 상태 필드가 없음** | 전체 수집 시 "이번 회차 목록에서 사라진 건"을 취하·만료(`CANCELLED`)로 판정합니다. |
| 완제 API의 `MAIN_INGR_ENG`가 **알파벳순으로 재정렬**되어 한글 성분과 순서가 대응하지 않음 | 복합제에서는 영문명을 개별 성분에 귀속시키지 않고, 단일제일 때만 사용합니다. |
| 두 API 모두 **변경분만 주는 파라미터가 없음** | 증분 수집도 목록은 전량 받아오되, 마스터와 비교해 달라진 것만 이력에 기록합니다. |
| **`pageNo` 페이징의 정렬이 불안정** | 아래 "페이징 불안정성" 참조. 2-pass 수집 + 취하 후보 개별 검증으로 보정합니다. |

### 페이징 불안정성 (반드시 알아야 할 사항)

같은 데이터로 전량 수집을 두 번 돌리면 결과가 일치하지 않습니다. 실측에서
완제의약품 쪽 약 **1,100건(약 2.6%)** 이 한 회차에서 빠졌다가 다음 회차에 다시
나타났고, 빠진 건들을 `item_seq`로 개별 조회하면 **모두 정상 존재**했습니다.
즉 품목이 사라진 게 아니라 크롤 중 페이지 경계에서 누락된 것입니다.

보정 없이 두면 매달 허위 "신규 1,100건 / 취하 1,100건" 알림이 발생합니다.
두 겹으로 막습니다.

1. **누락 보정 수집(`passes=2`, 기본값)** — 전량 크롤을 두 번 돌려 PK 기준 합집합을
   만듭니다. 1회 누락률이 `p`면 2회 모두 누락될 확률은 `p²`로 떨어집니다.
   대신 수집 시간이 배가 됩니다(1-pass 약 4분 → 2-pass 약 8분).
2. **취하 후보 개별 검증** — 그래도 목록에 없는 건은 `item_seq`(완제) 또는
   `ingr_kor_name`(DMF)로 재조회해 실제 삭제를 확인한 뒤에만 취하로 표시합니다.
   확인되지 않으면 `miss_streak`만 올리고 넘어가며, 검증을 끄면 **연속 2회 미관측**
   시에만 취하로 판정합니다.

수집이 끝나면 동기화 화면에 **수집 완전성** 표(API 총건수 / 수집 고유건수 /
추가 크롤로 복구한 건수 / 수집률)와 취하 후보 검증 결과가 표시됩니다.

## 3. 성분명 정규화 (`core/normalize.py`)

DMF와 완제의약품은 같은 성분을 다르게 적습니다. 조인 전에 두 종류의 키를 만듭니다.

| 키 | 규칙 | 예시 |
|---|---|---|
| `norm_ingredient_key` (EXACT) | 유니코드 NFKC → `[M코드]` 제거 → 괄호 블록 제거 → 소문자화 → 영숫자·한글 외 제거 → 이명 치환 → 광학이성질체 접두 통일 | `S-암로디핀베실산염2.5수화물` → `에스암로디핀베실산염25수화물` |
| `norm_base_key` (BASE) | EXACT 키에서 염·수화물·에스터 표기를 **접미·접두 양쪽으로** 반복 제거 | `말레인산암로디핀`, `암로디핀베실산염`, `베실산암로디핀` → 모두 `암로디핀` |

정규화가 처리하는 것들:

- **염/수화물 접미** 약 120종 — `베실산염`, `황산수소염`, `삼수화물`, `발레레이트` 등
- **염 접두(한국어 도치 표기)** — `말레인산암로디핀 = 암로디핀말레산염`, `인산코데인 = 코데인인산염`.
  단, 산 이름이 화합물명의 일부인 경우는 자르지 않습니다
  (`니코틴산아미드`, `살리실산메틸`은 그대로 유지)
- **광학이성질체 접두** — `S-암로디핀 = 에스암로디핀` (라틴 1글자 + 한글일 때만 치환하므로
  `esomeprazole` 같은 영문명은 영향받지 않습니다)
- **이명 사전** — `아세트아미노펜 = 파라세타몰`, `포도당 = 글루코스`, `비타민C = 아스코르브산` 등
- **복합제 분해** — `MAIN_ITEM_INGR`을 `|`로 나누고, 엑스제의 `이상 건조엑스로서 1.32g` 같은
  서술 항목은 걸러냅니다.

> 라세믹체와 광학이성질체는 **일부러 분리 유지**합니다. `암로디핀`과 `에스암로디핀`은
> 서로 다른 유효성분이므로 골격 키도 다릅니다.

## 4. 데이터 모델 (`core/db.py`)

| 테이블 | 키 | 용도 |
|---|---|---|
| `dmf_master` | `dmf_id` | DMF 등록 현황. 성분명, 원료 제조소, 제조국·주소, 등록업체, 상태, 관측 스냅샷 |
| `finished_drug_master` | `(item_seq, norm_ingredient_key)` | 완제 품목 × 주성분. 복합제는 성분 수만큼 행이 생깁니다 |
| `change_history_log` | `log_id` | NEW / MODIFIED / CANCELLED 로그. 변경은 **필드 단위로 1행** |
| `sync_run` | `run_id` | 수집 회차 이력 (스냅샷, 유형, 소요, 건수, 성공/실패) |
| `app_setting` | `key` | 인증키 등 로컬 설정 |

변경 감지 대상 필드는 `core/ingest.py`의 `DMF_TRACKED` / `FINISHED_TRACKED`에 정의돼 있습니다.
여기에 없는 필드(정규화 키, 영문명 보강값 등)는 로그를 남기지 않고 조용히 갱신됩니다.

## 5. 교차 결합 엔진 (`core/mapping.py`)

SQLite 마스터를 pandas로 올린 뒤 **DuckDB**로 조인합니다.

- **BASE 매칭(기본)**: `norm_base_key`로 조인 — 염 표기가 달라도 같은 유효성분이면 연결
- **EXACT 매칭**: `norm_ingredient_key`로 조인 — 염 표기까지 완전히 같은 경우만

BASE로 조인한 결과에서 두 키가 함께 일치하는 행에는 `EXACT` 라벨이 붙어,
"골격만 같은 매칭"과 "완전 일치 매칭"을 화면에서 구분할 수 있습니다.

무필터 전량 조인은 약 130만 행입니다. 조합 폭발을 막기 위해
**모든 필터(상태·국가·업체·기간·검색어)는 조인 이전에 각 마스터로 밀어 넣습니다.**
통합 검색어의 `LIKE` 평가도 조인 결과가 아니라 CTE 내부에서 끝냅니다.

### 통합 검색 문법

| 입력 | 의미 | 예시 결과 |
|---|---|---|
| `anhui poly` | **공백 = AND** — 모든 단어가 걸리는 행만 | Anhui Poly 제조소 2곳 (82행) |
| `"anhui poly"` | **따옴표 = 구(phrase)** — 연속 문자열 그대로 | 위와 동일 |
| `인도 \| 중국` | **세로줄 = OR** — 둘 중 하나 | 인도 또는 중국 제조 |
| `글리메피리드 anhui` | 조합 — 성분과 제조소를 동시에 | 해당 성분을 만드는 Anhui 제조소 |

국문·영문 모두 검색하며 대소문자를 구분하지 않습니다. `%`, `_` 는 문자 그대로 취급합니다.

> 초기 버전은 공백을 OR로 묶었는데, `anhui poly` 를 넣으면 `poly` 가 걸리는
> Polyethylene Glycol 류 성분이 대량으로 딸려 왔습니다. 사람이 단어를 나열할 때
> 기대하는 것은 AND이므로 기본을 AND로 두고, OR는 `|` 로 명시하게 했습니다.

**검색 대상** 선택기로 `성분명 / 원료 제조소 / DMF 등록업체 / 완제 제약사 / 완제품명 /
등록번호·품목코드` 중 원하는 항목만 지정할 수 있습니다(비워두면 전체).
다른 항목에 우연히 걸리는 결과를 배제할 때 씁니다.

**업체 지정**의 **원료 제조소 이름**·**완제 제약사 이름** 입력창은 이름 일부만 넣으면
곧바로 조회됩니다. 공백으로 띄운 단어는 모두 포함된 업체만 걸리고(AND), 대소문자는
구분하지 않습니다. 같은 회사가 `Zhejiang Hongyuan Pharmaceutical Co., Ltd.` 와
`…Co.,Ltd.` 처럼 쉼표·공백만 다르게 등록된 경우가 많아, 목록에서 표기를 하나씩 골라
여러 번 조회하지 않아도 되도록 부분 일치로 처리합니다. 입력하면 사이드바에 일치한
업체 수와 목록이 바로 표시되고, 하나도 없으면 경고가 뜹니다.

사이드바 **🔎 필터** 제목 옆 **초기화** 버튼은 그 페이지의 필터 입력을 한 번에 지웁니다.
검색어·업체·국가·기간은 비워지고, '유효만 보기' 같은 체크박스는 원래 기본값으로 돌아갑니다.
(입력값만 지우면 화면에 글자가 남아, 초기화할 때마다 위젯 키의 일련번호를 올려 새로 그립니다.)

**직접 선택** 드롭다운은 고른 값의 표기와 정확히 일치하는 업체만 매칭합니다.
이름 입력창과 함께 쓰면 **둘 중 하나라도** 해당하는 업체가 나옵니다(OR).
원료 제조소 조건과 완제 제약사 조건 사이는 AND 입니다.

**성분 매칭 방식**(골격 일치 / 염 표기까지 일치)은 **검색어와 무관합니다.** DMF 원료와
완제 주성분을 연결할 때 성분명을 어느 수준까지 같다고 볼지 정하는 옵션입니다.

그 밖의 사이드바 필터: DMF·완제 상태 토글, 국내/해외 구분과 국가 다중 선택,
등록일·허가일 범위, 변동 유형 필터.

**CSV는 모두 `utf-8-sig`(BOM)로 인코딩**되어 엑셀에서 한글이 깨지지 않습니다.

### 디자인 (`views/_theme.py`)

다크 네이비 사이드바 + 라이트 그레이 본문 + 흰색 카드 구조입니다. 색 토큰과 전역 CSS,
KPI 카드·카드 헤더 컴포넌트가 이 파일 한 곳에 모여 있어 여기만 고치면 전체 톤이 바뀝니다.

- **아이콘**: 본문 카드는 인라인 SVG(`ICONS` 딕셔너리), 사이드바 메뉴는 Streamlit 내장
  Material Symbols(`icon=":material/..."`). 외부 CDN·폰트에 의존하지 않아 사내망에서도
  아이콘이 깨지지 않습니다.
- **브랜드 블록**: `st.navigation`이 메뉴를 먼저 그리기 때문에 파이썬으로 위젯을 추가하면
  메뉴 아래에 붙습니다. 그래서 로고와 제목은 `[data-testid="stSidebarNav"]::before`
  의사요소로 그립니다(로고는 data URI SVG).
- **카드 판별**: Streamlit은 여러 레이아웃 블록을 같은 `testid`로 감싸므로, 컨테이너를
  통째로 겨냥하면 컬럼까지 흰 카드가 됩니다. `card_header()`가 넣는 `.cardhead`를 표식으로
  삼아(`:has(.cardhead)`) 실제 카드만 칠합니다.
- **차트**: 크기 비교용 단일 계열이라 색은 한 가지(`#2f6fe4`)만 쓰고 범례 없이 값 라벨을
  직접 붙입니다.

## Vercel 배포 (web/)

Streamlit 앱은 Vercel 에서 돌지 않습니다. 세션마다 WebSocket 을 유지하는 상주 서버이고,
59MB SQLite 파일에 쓰며, 4분짜리 수집 작업을 돌리기 때문입니다. Vercel 은 요청마다
떴다 사라지는 서버리스 함수만 실행합니다. 그래서 **조회 화면만 Next.js 로 다시 만들어**
`web/` 에 두고, 데이터는 Neon Postgres 에서 읽습니다.

| | 로컬 Streamlit (`app.py`) | Vercel (`web/`) |
|---|---|---|
| 데이터 수집·정규화 | ○ 담당 | × (읽기 전용) |
| 상세 조회 / 종합 현황 / 변경 이력 | ○ | ○ |
| CSV 내보내기 | ○ | ○ (`/api/export`) |
| 저장소 | 로컬 SQLite | Neon Postgres |

수집은 계속 사내 PC 의 Streamlit 앱이 담당하고, 그 결과만 Postgres 로 밀어 올립니다.

### 배포 절차

```bash
# 1) Neon Postgres 연결 (최초 1회, 브라우저에서 약관 동의 필요)
cd web && vercel integration add neon

# 2) 연결 정보 내려받기
vercel env pull .env.local

# 3) 로컬 수집 결과를 Postgres 로 적재 (약 15만 행)
cd .. && pip install "psycopg[binary]"
python scripts/push_to_postgres.py

# 4) 배포
cd web && vercel deploy --prod
```

수집을 새로 돌린 뒤에는 3번만 다시 실행하면 배포본에 반영됩니다
(스키마를 건드리지 않으려면 `--skip-schema`).

### 알아둘 점

- Vercel 프로젝트의 **Root Directory 는 `web`** 입니다. GitHub 자동 배포를 연결한다면
  프로젝트 설정에서 Root Directory 를 `web` 으로 지정해야 합니다.
- 배포본에는 **데이터 동기화 화면이 없습니다.** 인증키를 클라우드에 두지 않기 위한
  선택이며, 수집은 로컬에서만 실행합니다.
- 기본적으로 Vercel **Deployment Protection** 이 켜져 있어 배포 URL 은 팀 구성원만
  열 수 있습니다. 사내에 공유하려면 Vercel 프로젝트 설정에서 보호를 조정하세요.
